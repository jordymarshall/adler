# Adler reference documents

Start with these three documents:

| Document | Purpose |
| --- | --- |
| [Product principles](product-principles.md) | What Adler is, the accepted product direction and the principles each iteration must preserve. |
| [Coaching engineering](method/coaching-engineering.md) | How the shared coaching system should reason, use evidence, retain learning and support the product. This is the engineering design, not a claim that every target capability is implemented. |
| [Decisions and remaining work](product-structure-status.md) | What the grilling has settled, what the prototypes demonstrate, what remains in production and the next unresolved decision. |

Keep these foundations alongside them:

- [Current Adler method](method/adler-method.md): the implemented runtime contract and its limits.
- [Behavioural-science synthesis](research/behavioural-science-synthesis.md): the research base, evidence grades, source links and transfer limits. Historical product mechanics in the synthesis do not override current accepted direction or strengthen the evidence.
- [Domain glossary](../CONTEXT.md): the meanings of goal, plan, milestone, action, experiment, insight and related records.

The [accepted second-pass design](product-coaching-second-pass.md) develops the current iteration; its [evidence review](research/coaching-product-evidence-review.md) supports and qualifies it. The [older implementation checklist](implementation-checklist.md) records an earlier release and should not be read as completion of the newer structure work.

Prototype sources and visual decisions are preserved on the [prototype archive branch](https://github.com/jordymarshall/adler/tree/prototype/goal-views-integrated/docs/prototypes/goal-views-integrated). They are design references, not deployed application code.
